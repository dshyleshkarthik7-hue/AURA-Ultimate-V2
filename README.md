# AURA Perception V2

Educational Indian multilingual object-recognition prototype. The Python app runs locally; the browser demo loads OpenCV.js and optional detector assets from external CDNs and is not fully offline.

## Objects
Steel Glass, Steel Water Bottle, Bottle Gourd.

## Languages
English, Hindi, Telugu, Tamil, Gujarati.

## Architecture
The Python perception stack runs locally with NumPy/OpenCV and a from-scratch classifier. The browser consumes the same NPZ model artifact encoded as base64 and the same OpenCV v1 329-value feature contract. Browser feature extraction uses OpenCV.js, including the configured center ROI, resize, HSV histogram, Sobel orientation histogram, and texture statistics.

The web demo uses captured-background motion segmentation with OpenCV.js GrabCut fallback, suppresses crops overlapping detected people, provides position/size guidance, and requires four stabilized view changes before reporting a verified result. The four views are deliberately named view_1 through view_4: the browser does not infer physical front/left/right orientation from motion alone.

Training uses balanced class weights and validation temperature calibration. **The current trainer uses random image-level splits, not session-safe splits**, so adjacent frames may leak between partitions and reported metrics can overstate generalization. Training now splits by capture-session directory and refuses to report a split if a class has fewer than three sessions. Use `collect.py` separately for each capture session; legacy flat folders do not contain reliable session metadata and must be recollected. Unknown-object evaluation is available when independently collected `dataset/unknown/` examples are supplied. Automatic pseudo-label promotion is disabled because teacher-generated labels are not independent ground truth.

## Verification
Run:
`python -m unittest discover -s tests -p "test*.py"`
`python scripts/validate_web_contract.py`
`node --check web/app.js`
`node tests/web_smoke.js`
`node tests/browser_integration.mjs`

The browser integration test launches Chromium, loads OpenCV.js, runs the browser feature extractor on deterministic pixels, and checks the 329-value finite feature contract plus the context UI. This is a browser smoke/contract test, not proof of exact numerical parity with Python; exact cross-runtime parity remains a validation task.

## Quick start
1. Create and activate a Python virtual environment.
2. `pip install -r requirements.txt`
3. `python -m unittest discover -s tests -p "test*.py"`
4. `python train.py`
5. `python evaluate.py`
6. `python scripts/generate_model_card.py`
7. `python app.py`

After changing `config.yaml`, run `python scripts/export_web_config.py` and `python scripts/export_web_model.py`.

## Evaluation discipline
Augmented frames are never treated as independent evaluation evidence. For deployment claims, collect independent camera sessions and an independently labelled unknown-object set. Pseudo-label self-training is not ground-truth labelling. The deprecated automatic pseudo-label cycle intentionally exits without collecting data or promoting a model. Any future retraining workflow must use independent, human-labelled session-held-out evaluation.

For the browser, seven-frame temporal stability is not treated as seven independent photographs: final verification additionally requires four stabilized view changes. This is user-guided multi-view evidence, not a substitute for a professionally labelled benchmark.

## Dataset
`dataset/MANIFEST.csv` is generated by training, but CI does not currently validate its contents against every committed image. The current dataset is imbalanced; training compensates with balanced class weights. Additional independent sessions remain necessary.

## Browser limitations
The optional COCO-SSD person detector is loaded from a CDN, so the browser demo is network-dependent when that detector is enabled. Camera, browser CPU/memory, and detector latency must be measured on representative hardware before deployment claims. Production claims additionally require independently collected sessions and human-verified unknown labels.


## Context Intelligence + PayPal Sandbox

The repository also contains a context graph and a disabled checkout demo.

### Context reasoning

- The browser UI now has an **AURA / Context Intelligence** panel under the existing perception UI.
- Enter comma-separated labels such as `laptop, monitor`, then ask a question about connections, fit, or purchasing. The current stable AURA detection can be added with **Use AURA detection**.
- The panel presents object nodes, explicitly tentative relations, confidence, and missing evidence. Generic port information and sample prices are illustrative; this does not certify fit, safety, or device compatibility.
- Python integration lives in `aura/context_intelligence.py` and `aura/context_adapter.py`. The adapter accepts a result from `PerceptionEngine.predict()` and refuses to treat an unstable prediction as a confirmed object.

### Local web preview

Because the payment endpoints are Netlify Functions, use Netlify CLI to preview the web app and functions together:

1. Install Node.js and Netlify CLI.
2. From the repository root run `npm install -g netlify-cli`.
3. Run `netlify dev` and open the local URL printed by the CLI.
4. Checkout is deliberately disabled while the payment flow is reviewed; context reasoning remains available.

### PayPal Sandbox configuration

Checkout is disabled by the public PayPal configuration endpoint. Do not configure live credentials or expect checkout to work. Sandbox-only re-enablement requires buyer-bound orders, durable idempotent order storage, verified webhook processing, and end-to-end tests.

Payment endpoints are pinned to PayPal Sandbox, and the checkout UI remains disabled. No live payment processing is supported.

**Do not use real payments for the hackathon demo.** Keep Sandbox enabled. This demo has no fulfilment, shipping/tax, persistent order ledger, webhook verification, account/session ownership, rate limiting, or production merchant onboarding. Before live commerce, those controls and end-to-end testing are required. The listed USD prices are test fixtures, not live offers. No PayPal credentials or payment results are included in this repository.

### Privacy and accessibility

AURA's camera inference remains browser-side and frames are not sent to these context/checkout endpoints. The context form supports keyboard use, live result announcements, optional speech output, and opt-in browser speech recognition. Browser speech recognition may be processed by the browser or its provider; check the provider's privacy terms before enabling it.


## Context Intelligence + PayPal Sandbox

AURA now includes a relationship-reasoning panel below the perception interface. Enter object labels, ask about compatibility/fit/purchasing, and optionally provide real measurements or exact device models. The browser sends labels and structured text—not camera frames—to the serverless context endpoint. The endpoint returns an inspectable graph, evidence gaps, recommendations, and limitations.

- [Context Intelligence setup, AI configuration, and PayPal details](CONTEXT_INTELLIGENCE.md)
- [Environment template](.env.example) — example names only; no secrets belong in Git.
- Context reasoning works without a language-model key. Optional conversational phrasing uses server-side `OPENAI_API_KEY` and can be disabled with `AURA_AI_ENABLED=false`.
- PayPal checkout is currently disabled. Server endpoints are pinned to Sandbox; do not use live credentials.

**Important:** this remains a hackathon/demo integration, not production-ready commerce. Verified webhook events are acknowledged but not persisted and do not trigger fulfilment. Durable order/event storage, idempotent processing, buyer ownership, inventory, refunds/disputes, tax/shipping, and end-to-end merchant testing remain before live payments. Generic compatibility and fit are hypotheses unless verified against exact device specifications and measurements.
